# Editorial model — 体験談メディアとしての見せ方

Tomokichi Diary は「旅先を検索するサイト」ではなく、**ともきちの旅の体験談を読むメディア**として見せる。
旅先情報や実用情報は、体験談の延長線上に置く。

## 2 種類のタグ

|            | `tags`（既存）                         | `experienceTags`（新設）                                               |
| ---------- | -------------------------------------- | ---------------------------------------------------------------------- |
| 意味       | 記事の内容（場所・テーマ・キーワード） | その旅が**どんな体験・感情だったか**                                   |
| 語彙       | 自由（増えてよい）                     | 閉じた 8 語（`packages/domain/src/entities/experience.ts`）            |
| 保存       | `article_tags`（relation）             | `articles.experience_tags`（JSON 配列、migration 0009）                |
| 主な使い道 | 検索・回遊・補助                       | HOME の「どんな旅の話を読む？」、`/posts?experience=…`、記事の関連導線 |

### 語彙

| 値              | 表示名          | 付ける目安                                                   |
| --------------- | --------------- | ------------------------------------------------------------ |
| `exciting`      | ワクワク        | 着いた瞬間から胸が高鳴った                                   |
| `moving`        | 感動            | 景色や人に心が動いた                                         |
| `thrilling`     | ハラハラ        | トラブル・冷や汗・ぼったくり・遅延                           |
| `disaster`      | これは終わった… | もうダメだと思った（島に連れて行かれかけた、11 時間足止め…） |
| `funny`         | 笑える          | 失敗や寝坊など、今思うと笑える                               |
| `discovery`     | 発見            | 行って初めて分かったこと・実用の気付き                       |
| `challenge`     | 挑戦            | 体力や勇気が要ったこと                                       |
| `unforgettable` | 忘れられない    | 今でもふと思い出す                                           |

- データには**識別子だけ**を持たせる。表示名・一言・色は `apps/web/src/lib/experiences.ts` で管理し、文言を変えても記事は触らない。
- 1 記事 1〜3 個が目安。純粋な手続きガイド（空港アクセス比較など）は無理に付けなくてよい。
- 語彙を増やすときは `EXPERIENCE_TAGS` と `EXPERIENCE_COPY` の両方に足す。消すときは、読み込み側が未知の値を捨てるので既存データは壊れない。

### 付け方

- API: `PUT /v1/admin/articles/:id/experience-tags` `{ "experienceTags": ["moving"] }`（revision は作らない。`updatedAt` も変えない）
- まとめて: `pnpm db:restore-local` → `pnpm content:experiences tags.yaml` → `pnpm export:data`

  ```yaml
  egypt4: [thrilling, unforgettable]
  turkey3: [moving, unforgettable]
  ```

初回分（102 記事）はタイトルと要約から機械的に付けた**たたき台**。本人が見直す前提。

## HOME の編集的な選定

「どの記事を HOME の先頭に出すか」は記事の性質ではなくページの編集判断なので、記事 metadata ではなく
`apps/web/src/lib/editorial.ts` で持つ。

- `BEST_EPISODES` — 「まず読んでほしい旅の話」。`featuredTitle`（見せタイトル）と `hook`（一言）を持てる。先頭が大きく出て、全件が Hero のスライドにもなる。
- `SELECTIONS` — 「ともきち的ランキング」。人気順ではなく体験軸（ハラハラ、後悔、感動、また行きたい街…）。
- 記事は slug で指す。非公開・削除された記事は自動で落ちる。

`hook` は本文に書いてある事実だけで書く（誇張しない）。

## HOME の構成（共有ラフ準拠）

1. Hero（コピー固定。スライドはベストエピソード、文字の下に暗幕）
2. どんな旅のエピソードをお探しですか？（検索 → 体験タグのチップ → Adaptive Discovery）
3. ともきちのベストエピソード（写真大きめ、左右矢印のカルーセル）
4. 新着（横スクロール、♡付き）
5. 地図から見る、ともきちの旅
6. ともきち的ランキング（横スクロール。ハラハラ／後悔／感動／また行きたい／ごはん、各 5 位まで）
7. ギャラリー（スマホは 2×2）
8. About（本人の写真をテープ留めの写真風に）
9. さぁ、あなたはどこへ行く？（全ページのフッター上。「いいねした旅」「共有した旅」の一覧）
10. フッター

### Adaptive Discovery（2. の直下）

気分タイルを選ぶと、ページ遷移せずに下の「シーン」が切り替わる。並べ替えではなく、**気分そのものを体験させる小さな遊び**を 1 気分 1 つ持つ。ルールベースで AI は使わない。
選定・シーン対応は `apps/web/src/lib/home-discovery.ts`（純関数）、描画と動きは `components/home/discovery/*Scene.astro`、
シーンの開始・停止は `lib/discovery-scenes.ts`、見た目は `styles/pages-home-discovery.css`。

| シーン                      | 体験タグ        | 遊び                                                       |
| --------------------------- | --------------- | ---------------------------------------------------------- |
| `board`（出発案内板）       | `exciting`      | 行き先がパタパタ表示で決まり、指した便の写真が機窓に出る   |
| `cinema`（シネマ）          | `moving`        | 暗転した劇場で 1 枚ずつゆっくり寄り、タイトルが字幕で出る  |
| `pulse`（心拍モニター）     | `thrilling`     | 記事に触れると心拍が上がり、カードが震える                 |
| `collapse`（崩れ落ちた旅）  | `disaster`      | 雨の中に写真が落ちて傾き、触れると持ち直す                 |
| `gacha`（笑い話ガチャ）     | `funny`         | ハンドルを回すとカプセルから 1 話出てくる                  |
| `lens`（虫眼鏡で探す）      | `discovery`     | ぼけた写真を虫眼鏡でなぞるとピントが合い、「発見!」が付く  |
| `letters`（挑戦状）         | `challenge`     | 封蝋を切ると挑戦状が出てくる                               |
| `develop`（記憶を現像する） | `unforgettable` | 暗室でチェキが現像され、振ると早まり、全部出ると明るくなる |

- 出すのは記事にあるデータだけ（便名・座席・事件の詳細などを作らない）。心拍の数値は読者の「気分」の演出で、記事の事実ではない。
- JavaScript なしでは各シーンはふつうの一覧として読める。`prefers-reduced-motion` では動き（パタパタ、自動再生、雨、震え、現像）を止める。
- 選択状態は `/?homeExperience=<tag>`（canonical は `/` のまま）。未知の値は無視して URL から消す。
- 未選択時は `moving`。他のタグは `<template>` に入れておき、選ばれるまで画像を読まない。
- 対応を変えるときは `DISCOVERY_TEMPLATES` だけを直す。

「いいねした旅」「共有した旅」はこのブラウザの localStorage にだけ保存する（`apps/web/src/lib/my-trips.ts`）。
いいね数そのものはこれまで通りサーバーで数える。

## 今後の記事執筆ルール

本文は **体験 → 感情 → 実用情報** の順を意識する。何が起きたか、どう感じたか、次に行く人に何が役立つか。
既存記事の全面リライトはしない。
