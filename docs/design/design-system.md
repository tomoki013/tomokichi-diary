## 1. 目的と基本方針

本プロジェクトは、Tomokichi Diaryの全面リニューアルではない。

既存サイトのコンテンツ、機能、ブランド資産を維持しながら、ビジュアルデザイン、情報設計、コンポーネント、アクセシビリティを体系的に整備する。

**デザインコンセプト：旅の日記 × トラベルマガジン**

目指す体験は「柔らかく親しみやすいが、洗練されていて、情報が明確に伝わる旅行メディア」。

単なる高級感や装飾性ではなく、旅への好奇心、発見、信頼を視覚的に表現する。

### 変更しないもの

- ブランドコピー「一生モノの体験を、もっと身近に。」
- 実体験を中心とした旅行メディアとしての方向性
- 既存記事、URL、コンテンツの基本構造
- 気分別探索、記事検索、地図、ギャラリーなど既存の主要機能
- 現在のサイトが持つ親しみやすさと旅ごとの個性

## 2. ブランドとユーザー

### ブランドコピー（固定）

**一生モノの体験を、もっと身近に。**

### メディアコンセプト

定番の観光だけでは出会えない、現地の日常や文化、まだ知らない場所、そこでしかできない特別な体験。

実際の旅で得た発見や感動を伝え、いつもの海外旅行をもっと面白く、豊かにする。

### メインターゲット

海外旅行を複数回経験し、定番の観光に加えて、さらに深い発見や体験を求めている20〜30代中心の旅行好き。

### 解決する課題

1. 自分がまだ知らない場所・体験を発見しにくい
2. 現地のリアルな雰囲気や経験が伝わりにくい
3. 自分に合う体験か判断しにくい
4. 興味を持っても実現方法が分かりにくい

### デザインが担う役割

- 写真や編集表現によって新しい体験への興味を生み出す
- 検索・気分・地域など複数の入口から記事へ導く
- 旅行記では没入感、実用記事では明確さを優先する
- 実体験の信頼性と、情報へのアクセスしやすさを両立する

## 3. デザイン原則

以下の7原則をすべてのページ・コンポーネントに適用する。

### 3.1 Visual Hierarchy — 視覚的階層

- ひとつの領域につき主役となる情報を明確にする
- 見出し、写真、本文、補足情報に視覚的優先順位を設ける
- サイズ、ウェイト、余白、配置で重要度を伝える
- 強調の多用を避ける

### 3.2 Contrast — コントラスト

- WCAG 2.2 AAを最低達成基準とする
- 通常文字4.5:1以上、大きな文字3:1以上
- 識別に必要なUIの境界やアイコンは3:1以上
- 本文は可能な範囲で7:1以上を目指す
- 色だけで選択・エラー・状態を伝えない
- 写真の上に文字を載せる場合は実際の表示条件で検証する

### 3.3 Alignment — 整列

- 共通グリッドを使用する
- カード内のタイトル、メタ情報、操作位置を揃える
- 不必要な中央揃えや左右の不統一を避ける
- 文章は原則左揃えとする

### 3.4 Proximity — 近接

- 関連情報は近くに配置する
- 異なる情報群は余白で明確に分離する
- 見出しと直後のコンテンツの関係を強くする

### 3.5 Consistency — 一貫性

- 色、文字、余白、角丸、影、操作状態をトークン化する
- 共通コンポーネントを再利用する
- 気分別UIの演出は変化しても、基本操作は統一する

### 3.6 Whitespace — 余白

- 4pxを最小単位、8pxを基本単位として余白を設計する
- 写真と文章が呼吸できる空間を確保する
- 単に広い余白ではなく、情報のまとまりを表現する

### 3.7 Authenticity — 実体験の尊重

- 実際に撮影した旅行写真を主役にする
- 写真をブランドカラーに無理に合わせない
- 旅先ごとの色彩や空気感を残す
- 加工や装飾によって実体験の印象を誤認させない

## 4. カラーシステム

### 4.1 基本カラー

| カラー     | HEX     | 用途                         |
| ---------- | ------- | ---------------------------- |
| Soft Clay  | #C9927D | 温かみ、アクセント背景、装飾 |
| Milk Ivory | #FAF8F4 | ページ背景、柔らかい余白     |
| Warm Slate | #4C565B | 主要文字、見出し、濃色UI     |

ブランドの基本色はこの3系統とする。

ただし、実際のUIではアクセシビリティを維持するため、同系統の濃淡および白・ニュートラルカラーを使用できる。

「3色まで」とは、すべてのHEX値を3つに限定する意味ではなく、視覚的に主役となる色相を絞る方針とする。

### 4.2 セマンティックカラー

| Token              | HEX     | 用途                       |
| ------------------ | ------- | -------------------------- |
| background.base    | #FAF8F4 | ページ背景                 |
| surface.base       | #FFFFFF | カード・入力面             |
| surface.warm       | #EBD5CA | 柔らかい強調領域           |
| text.primary       | #1B2022 | 主要文字                   |
| text.secondary     | #3A4246 | 補助文字                   |
| brand.soft         | #C9927D | 装飾・背景                 |
| brand.strong       | #97594E | CTA・重要リンク            |
| brand.strongHover  | #854B43 | CTAホバー                  |
| border.decorative  | #E8E5E0 | 装飾的な区切り             |
| border.interactive | #8D7F79 | 識別が必要な入力欄等の境界 |
| focus.ring         | #1B2022 | キーボードフォーカス       |

エラー・警告・成功などの状態色は別途セマンティックトークンとして定義し、表示背景とのコントラストを検証する。装飾目的で使用するブランドカラーとは区別する。

### 4.3 コントラストの基準値

| 組み合わせ                      |    比率 | 用途判定               |
| ------------------------------- | ------: | ---------------------- |
| Warm Slate / Milk Ivory         | 15.51:1 | 通常文字可、AAA        |
| Secondary Text / Milk Ivory     |  9.67:1 | 通常文字可、AAA        |
| Strong Accent / Milk Ivory      |  5.14:1 | リンク・通常文字可、AA |
| White / Strong Accent           |  5.45:1 | CTA文字可、AA          |
| Warm Slate / Warm Surface       |  5.34:1 | 通常文字可、AA         |
| Interactive Border / Milk Ivory |  3.64:1 | 必要なUI境界に使用可   |
| Soft Clay / Milk Ivory          |  2.51:1 | 通常文字には使用禁止   |
| Warm Slate / Soft Clay          |  2.83:1 | 文字配置禁止           |

上記は指定した不透明色同士で計算した値。透過、画像、グラデーション、ホバー、重ね合わせがある場合は別途検証する。

**重要：Soft Clayは通常文字の色として使用しない。**

## 5. タイポグラフィ

### フォント方針

- 編集的な大見出し：Noto Serif JP
- 本文、UI、ナビゲーション、検索、フォーム：Noto Sans JP
- 日本語・英語を含む表示で、書体の追加を必要最小限に抑える
- フォントロード失敗時は適切なシステムフォントにフォールバックする

### 基本スケール

| 要素     | 推奨                   |
| -------- | ---------------------- |
| Hero     | 32〜48px、レスポンシブ |
| H1       | 30〜40px               |
| H2       | 24〜30px               |
| H3       | 20〜24px               |
| 本文     | 16〜18px               |
| 補足     | 14〜15px               |
| UIラベル | 原則14〜16px           |

本文の行間は1.7〜1.9程度を基準とし、見出しは1.3〜1.5程度とする。文字を画像に変換して表示しない。

## 6. レイアウト・共通部品

### 基本ルール

- 余白スケール：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px
- ページ最大幅：概ね1160〜1200px
- 記事本文幅：概ね680〜760px
- モバイル左右余白：16〜20px
- カード角丸：8〜12pxを基本
- 影は控えめにし、必要な階層表現のみで使用
- タッチターゲットは原則44×44px以上を推奨する

### 共通コンポーネント

- Header / Navigation
- Footer
- Search Field
- Primary / Secondary Button
- Article Card
- Editorial Feature Card
- Category / Mood Chip
- Breadcrumb
- Section Heading
- Pagination
- Form Controls
- Loading / Empty / Error State

基本形状、余白、フォーカス、ホバー、選択状態を統一する。

## 7. 写真・ビジュアル表現

- 実写を優先し、コンテンツに無関係な素材で装飾しない
- ヒーロー写真は没入感を重視
- 記事カードの標準比率は4:3を候補とし、既存比率との比較後に確定
- 写真の被写体が不自然に切れないよう表示位置を調整可能にする
- 写真上の文字は、十分な濃度のオーバーレイまたは独立した文字面で可読性を確保
- 遅延読み込み、適切な解像度、レイアウトシフト防止に対応
- 意味のある写真には適切な代替テキストを設定する

写真の雰囲気に応じてカードレイアウトや編集表現に変化を持たせてもよい。ただし基本操作や情報の順序に一貫性を保つ。

## 8. ページ別デザイン方針

### Home

既存のHero、気分別探索、ベストエピソード、新着、旅の地図、ギャラリー等を維持する。

主な改善点：

- ヒーローの可読性と写真の見せ方
- セクションごとの視覚的階層
- 記事の発見につながる導線の明確化
- 異なるコンテンツ群の余白と配置の統一

### Blog / Article Listing

- 検索・絞り込み・並び替えの視認性改善
- 記事カードの情報順序と密度の統一
- 選択中フィルタの明確化
- 検索結果なし・ローディング状態の改善

### Article Detail

- タイトル・写真・本文の読みやすさを優先
- 本文と目次、注意書き、補足情報の階層を整理
- 旅行記と実用記事で適切な情報表現を使い分ける
- 関連記事への導線を自然に配置

### Destinations / Gallery / Collections

- 既存の探索機能を維持
- 地図・写真・一覧など異なる形式でもUIルールを共有
- 国や地域、写真カテゴリ、コレクションの見つけやすさを高める

### About / その他

- 主要カラー、見出し、余白、リンクの統一
- サイトの信頼性に関わる表記を維持
- 法務・運営関連ページの可読性を確保

## 9. アクセシビリティ・品質

WCAG 2.2 AAを目標とし、以下を満たすこと。

- 文字・非文字要素の必要コントラスト
- 適切な見出し階層と意味のあるHTML
- キーボード操作と可視フォーカス
- フォーカス時の要素の隠れ防止
- 文字200%拡大時の利用可能性
- 320px幅相当での不要な横スクロール防止
- 色だけに依存しない状態表現
- reduced-motionへの対応
- 適切なフォームラベル
- 画像の代替テキスト
- レスポンシブ表示

## 10. 成功基準

完成の判断は、見た目の主観だけでは行わない。

1. 既存コンテンツ・主要機能が維持されている
2. コアカラーが共通トークンで管理されている
3. 文字・操作要素が指定したコントラスト基準を満たす
4. 画面間でフォント・余白・ボタン等のルールが統一されている
5. 写真と記事の個性が損なわれていない
6. モバイル・デスクトップで読みやすく、操作可能
7. SEO、ページ表示性能、主要な分析イベントが不必要に変更されていない
8. 変更前後の比較と検証結果が確認できる

## 11. 非目標・禁止事項

- サイト全体の作り直し
- ブランドコピーの変更
- デザイン目的の既存記事改稿
- URLやSEO設定の無関係な変更
- 新しい探索機能の勝手な追加
- 不必要なライブラリ・フレームワーク導入
- 写真全体への強制的なブランドカラーフィルタ
- デザインシステムを無視した場当たり的な色指定

**最終原則：既存サイトの良さを残しながら、より明確に、より美しく、より使いやすくする。**
