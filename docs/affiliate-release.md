# アフィリエイト正式公開

2026-10-17。所有者からTrip.com・Omio・Agodaの正式リンク掲載と管理画面への反映を指示され、Phase 2の準備専用から公開対応へ拡張しました。

## 仕組み

既存のD1正本→記事の公開版→export→静的HTMLを維持します。管理画面の案件と記事内マーカーを使用し、外部ASPの審査・レポート・報酬を自動同期するAPIは追加しません。

公開条件はサイトのaffiliateEnabled、記事モードaffiliate/hybrid、配置ready、案件readyとpublicationApproved=true、確認日時、見出し、正式なHTTPS提携リンクです。既定は無効・未承認で、古い案件は承認を得るまで公開しません。対応先はTrip.com・Agoda・Omioの検証済みトラッキングURL形式に限定します。

公開projectionはキー・位置・サービス名・見出し・説明・URL・表示形式だけを固定します。管理メモ、案件ID、内部案件名、確認記録、下書き、未承認案件、画像は公開しません。exportの書出し・読込みとWebビルドでも検証します。本文マーカーの消失・重複・他枠との競合は別位置へ自動移動しません。現在の公開形式はテキスト／予約カードで、写真付きは管理プレビューのみです。

記事冒頭と各紹介に広告表記を付け、リンクはrel=sponsored nofollow noopenerです。料金・割引・最安値の保証や利用していないサービスの体験談を作りません。紹介は原則記事内の関連段落後、導入から600字以上かつ見出し後、画像・関連記事の隣を避けます。最大2件、AdSenseは従来どおり1枠で、既存の配置実験設定を維持します。外部スクリプト、iframe、画像、追加識別子を読み込みません。

追加migrationはありません。案件の公開承認を既存JSON payloadへ後方互換で保存します。案件更新と使用中の記事の公開待ちrevisionの作成、サイト方針変更と影響記事の公開待ち化は同じD1 batchで原子的に行います。

## 管理操作

1. 収益化→アフィリエイト案件で正式リンクと紹介文を入力。提携状態・リンク先・掲載条件を確認し、確認日時を記録、掲載準備済みを選び、公開承認して保存。
2. 広告設定で承認済みアフィリエイトの公開を許可。記事編集でhybridを選び、既存AdSense設定・実験IDを保って紹介枠を作成、案件を割り当てる。
3. 関連する本文段落の後へ配置し、本文と収益化設定を保存。対象記事の「変更を公開」で公開版へ固定し、サイト反映完了を確認。
4. 料金・条件の確認は予約先で行うことを明記。一般的な予約比較案内と自分の利用体験を区別する。

案件のURL等を管理画面で編集すると公開承認を解除します。正式リンクと条件を再確認して承認・保存してください。案件の変更・一時停止・アーカイブは使用中の記事を公開待ちにします。すでに配信済みのHTMLは静的なため、対象記事を再公開して反映完了を確認するまでは直前の公開版です。サイト方針の切替も同様です。未公開の編集がある記事は勝手に公開せず、編集内容を確認してください。

緊急停止: WebビルドにAFFILIATE_ENABLED=falseを渡して通常フローで配信。AdSenseとその実験は維持します。案件・配置データを削除しません。

## 検証と制約

契約・ドメイン・不正URL、未承認／下書き／停止／確認日時なしの非公開、公開allowlist、マーカー不整合、AdSenseとの独立、案件・サイト方針更新から再公開までを単体・HTTP／実SQLiteで検証します。隔離スナップショットは既存fixtureコマンドに--affiliatesを追加すると生成できます。外部リンクをクリックする試験やテスト予約は行いません。

実収益はASPが返す取得済みの粒度だけを扱います。クリックから報酬を推計せず、AdSenseと合算・二重計上しません。外部ASPの承認状態や報酬の自動取込は未実装で、ダッシュボードの案件は所有者確認の登録内容です。実際のサービス登録・対象記事・本番確認結果はローカルの反映記録へ残し、個人情報・契約固有の条件・実収益をGitへ記録しません。
