# 旅先の小話｜企画・編集方針 v1.0

2026年10月18日。Tomokichi Diaryの主力シリーズの一つとして制作する。

**知らなくても楽しい。知ると、もっと面白い。**

旅先で目にした景色、建築、文化や習慣の「なぜ？」を、短く気軽な読み物にする。旅を楽しむための必修知識にはせず、一つの発見を持ち帰れる記事を目指す。

## 編集の基準

| 項目           | 方針                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------- |
| 形式           | 疑問や意外な事実から入る、1記事1発見の読み物                                                       |
| 長さ           | 本文300〜600字を目安。写真・出典・関連記事のURL表記は字数に含めない                                |
| 読者           | 専門知識を前提にせず、一般の旅行好きが気軽に読める                                                 |
| 対象           | 本人が訪れた場所。個別スポット・観察内容は旅行記や写真と照合する                                   |
| 写真           | 本人が現地で撮影したものを優先。ない場合は候補確認を残し、他人の画像で代用しない                   |
| 語り           | 本文はです・ます調に統一。説明を詰め込まず、現地の景色と発見をつなぐ。全記事を同じ型に押し込まない |
| 体験           | 本人の記録にある経験だけを書く。会話・観察・当日の心情や学んだ時期を創作しない                     |
| 事実確認       | 管理機関・公的観光局・博物館・研究資料などを優先し、記事ごとに出典を付ける                         |
| 不確かな情報   | 伝説と事実を区別し、確定できない起源や日付、唯一・全部などの断定を避ける                           |
| タイトル       | 疑問・発見を自然に表す。調査後に範囲を限定・修正してよい。誇張や煽りは避ける                       |
| ネタバレ       | 発見を一つに絞り、現地での観察や驚きの余地を残す                                                   |
| 関連記事       | 対応する旅行記へ、内容に合う短い導線を添える                                                       |
| SEO            | 自然な表現を優先。検索向けの水増しや不自然な長文化をしない                                         |
| 収益化         | UXを優先し、広告・アフィリエイトを無理に挿入しない。今回の下書きは広告なし                         |
| 今回の保存状態 | **全22本を下書きで停止。公開も公開予約も行わない**                                                 |

## テーマの採用

名所の知られていない背景、景色や習慣の理由、歴史上の人物・出来事、旅の前後に知ると体験が豊かになる話を扱う。有名な話でも、タージ・マハルの建設背景のように旅の見方につながるなら採用する。

一般常識だけの説明、根拠の乏しい都市伝説、未解決の謎の断定、専門的すぎる技法紹介、旅行体験から離れた雑学は原則扱わない。未訪問の場所を訪問済みとして書かない。香港とボロブドゥール寺院は対象外。シンガポールは2026年3月の訪問記録を用いる。

## 構成と制作手順

自然な疑問・発見のタイトルに続き、景色の導入、発見・答え、必要最小限の背景、旅とのつながりを置く。本文に小見出しを無理に増やさず、内容によって構成を変える。

1. 本人の旅行記で訪問範囲と体験を確認する。
2. 一次資料を中心に調べ、中心にする発見を一つ決める。
3. 300〜600字程度の原稿を作り、対応する旅行記へ自然にリンクする。
4. 年代・固有名詞・因果関係と出典の対応、本人の体験との整合を点検する。
5. 写真の選定・代替テキスト、未確認点を別の編集メモへ残す。
6. CMSへ下書き保存し、保存内容と原稿の一致を確認する。明示的な公開指示があるまで、公開・予約へ進めない。

各Markdownのfrontmatterに地域、訪問記録、写真候補、出典、確認事項を保存する。CMS本文には読者向けの本文・写真・参考資料のみを入れ、編集メモは変更履歴に要点を残す。

## 公開順と育成

#001エッフェル塔、#002サントリーニの白い家の順を確定する。#003以降は候補順であり、日付を予約しない。

1〜10本は既存CMSとシリーズ一覧を使い、質と読み味を揃える。11〜30本では国・地域・ジャンルによる探しやすさと旅行記への導線を検討する。30本以降は日替わりの発見や訪問国別のコレクションも検討する。記事数は目安で、量産を目的にしない。

公開後は検索流入のほか、読了や旅行記への回遊を参考に改善する。
